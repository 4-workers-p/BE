# 신규 입사자 온보딩 (커머스플랫폼팀 · 백엔드)

이 문서는 팀에 새로 합류한 개발자가 첫 2주 동안 따라야 할 절차입니다. 사내 공통 온보딩(계정 발급, 장비 신청 등)은 인사팀 온보딩 가이드를 우선하며, 이 문서는 팀/저장소 특화 내용만 다룹니다.

## 1일차 체크리스트

- [ ] 사내 GitHub Organization 초대 수락, `commercehub-be` 저장소 접근 권한(Read) 확인
- [ ] 1Password(사내 시크릿 매니저) 팀 볼트 초대 수락 — **개인 계정으로 직접 크리덴셜을 주고받지 않습니다**
- [ ] Slack 채널 가입: `#commercehub-be`, `#commercehub-incident`, `#commercehub-release`
- [ ] 로컬 개발 환경 구성 ([`README.md`](../README.md) 4절 참고), 샘플 API 1건 호출 성공 확인

## 1주차

- [ ] `docs/architecture.md`, `docs/coding-convention.md`, `docs/domain-glossary.md` 정독
- [ ] 사수(멘토)와 1:1로 서비스 경계/이벤트 흐름 리뷰
- [ ] 난이도가 낮은 `fix/*` 티켓 1건 처리 후 PR 프로세스 경험 (`docs/branch-and-release-policy.md` 참고)
- [ ] 코드리뷰 최소 3건 관전(직접 리뷰어로 참여하지 않아도 코멘트 읽기)

## 2주차

- [ ] 온콜 로테이션 옵저버로 1회 참관 (실제 대응은 하지 않고 절차만 관찰)
- [ ] 스프린트 플래닝/회고 참석
- [ ] 담당 도메인 서비스 1개를 정해 오너십을 갖고 첫 `feature/*` 작업 착수

## 권한 신청 (필요 시에만, 최소 권한 원칙)

| 권한 | 신청 대상 | 승인자 |
| --- | --- | --- |
| 운영 DB 조회(Read-only) | 장애 분석이 필요한 경우에만 | 파트장 |
| ArgoCD 접근 | 배포 담당 로테이션 진입 시 | DevOps 파트 |
| PG 샌드박스 콘솔 | 결제 도메인 작업 시 | 결제 도메인 담당자 |

운영 DB에 대한 쓰기 권한은 원칙적으로 발급하지 않으며, 데이터 수정이 필요한 경우 반드시 배포 파이프라인(마이그레이션 스크립트)을 통해서만 처리합니다.

## 자주 하는 실수 (신규 입사자 대상 안내)

- 로컬 `.env.local`을 실수로 커밋 → `.gitignore`에 이미 포함되어 있으나, 강제로 `git add -f`를 사용하지 않도록 주의
- 다른 서비스 DB에 직접 붙어 조회 → 반드시 해당 서비스 API 또는 담당자에게 요청
- 재고/결제 로직에서 락 없이 수량을 증감 → PR 리뷰에서 반려 사유 1순위
