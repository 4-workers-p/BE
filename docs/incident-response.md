# 장애 대응 정책 (commercehub-be)

## 1. 심각도 분류

| 등급 | 정의 | 예시 | 대응 목표 시간 |
| --- | --- | --- | --- |
| SEV1 | 전체 서비스 장애, 결제 불가 | 결제 API 전면 장애, 게이트웨이 다운 | 인지 후 15분 내 대응 착수 |
| SEV2 | 일부 기능 장애 | 특정 카테고리 상품 조회 실패, 리뷰 등록 불가 | 1시간 내 |
| SEV3 | 경미한 이슈, 우회 가능 | UI 오탈자성 API 메시지 오류 | 다음 스프린트 내 |

## 2. 대응 절차

1. **인지**: 모니터링 알림(Grafana/Sentry) 또는 CS 접수를 통해 인지
2. **선언**: 온콜 담당자가 Slack `#commercehub-incident`에 심각도와 함께 공유, SEV1/2는 파트장 태그
3. **완화(Mitigation)**: 원인 파악 전이라도 트래픽 차단, 이전 버전 롤백 등으로 우선 영향 최소화
4. **근본 원인 조치**: 코드/설정 수정 후 `hotfix/*` 절차([`branch-and-release-policy.md`](branch-and-release-policy.md)) 진행
5. **종료 공지**: 정상화 확인 후 채널에 종료 공지
6. **포스트모템**: SEV1/2는 48시간 내 포스트모템 문서 작성(비난 없는 문화, 재발 방지 액션 아이템 포함)

## 3. 온콜 운영

- 온콜은 백엔드 파트 내 주 단위 로테이션이며, 담당자는 팀 캘린더에서 확인합니다.
- 온콜 담당자는 업무 외 시간에도 Slack 알림에 30분 내 반응해야 합니다(대응 자체가 아니라 "확인 중" 회신 기준).
- 온콜 담당자가 직접 해결 불가한 경우 도메인 담당자를 즉시 호출(Escalation)합니다.

## 4. 개인정보 유출 대응 (별도 필수 절차)

카드정보, 회원 개인정보 등 민감정보 유출이 의심되는 경우 일반 장애 절차와 별도로 아래를 즉시 수행합니다.

1. 즉시 정보보호팀에 별도 채널(`#security-incident`)로 보고 — 일반 장애 채널에 상세 정보 공유 금지
2. 유출 의심 로그/데이터 접근을 최소 인원으로 제한
3. 정보보호팀 지시 없이 임의로 로그를 삭제하거나 시스템을 재시작하지 않음(증거 보존)
4. 이후 절차는 정보보호팀 개인정보 유출 대응 매뉴얼을 따름 (이 저장소 범위 밖)

## 5. 포스트모템 템플릿 위치

사내 위키 `개발실 > 포스트모템 템플릿`을 사용하며, 필수 섹션은 타임라인, 영향 범위, 근본 원인, 재발 방지 액션 아이템(담당자/기한 명시)입니다.
