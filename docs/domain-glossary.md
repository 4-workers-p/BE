# 도메인 용어집 (기획 · 디자인 · 개발)

CommerceHub는 기획자/디자이너/개발자가 같은 대상을 서로 다른 단어로 부르는 경우가 많아 커뮤니케이션 비용이 컸습니다. 이 문서는 세 직군이 같은 개념을 어떤 용어로 부르는지 매핑하고, 코드/API에서 사용할 **표준 영문 필드명**을 확정합니다. 신규 용어는 이 표에 먼저 등록한 뒤 코드에 반영합니다.

## 상품/재고

| 기획 용어 | 디자인(화면) 용어 | 개발 표준명 | 설명 |
| --- | --- | --- | --- |
| 옵션 | 옵션 선택 UI | `optionGroup` / `optionValue` | 색상·사이즈처럼 상품에 딸린 선택지. `optionGroup`(예: 색상)이 여러 `optionValue`(예: 빨강/파랑)를 가짐 |
| 옵션조합 | - | `optionCombination` (= SKU) | 옵션 값들의 조합 하나가 실제 재고를 갖는 최소 단위. 기획 문서의 "품번"과 동일 개념 |
| 품절 | 품절 뱃지 | `soldOut` (boolean, SKU 단위) | 상품 단위가 아니라 **SKU(옵션조합) 단위**로 품절 여부가 결정됨 — 기획 시 "상품 품절"이라고 뭉뚱그려 쓰면 안 됨 |
| 재고 동기화 | - | `stock reconciliation batch` | 외부 창고 시스템(WMS)과의 재고 수량 정합성 배치. 실시간이 아니라 5분 주기 |
| 대표 이미지 | 썸네일 | `thumbnailImageUrl` | 목록/검색 결과에 노출되는 이미지. 상세 이미지(`detailImageUrls`)와 별도 관리 |

## 주문/결제

| 기획 용어 | 화면 상태명 | 개발 표준명(주문 상태 Enum) | 설명 |
| --- | --- | --- | --- |
| 주문 접수 | 결제 완료 | `PAID` | "주문 접수"는 결제까지 끝난 상태를 가리킴. 결제 전 임시 상태는 `PENDING` |
| 배송 준비중 | 상품 준비중 | `READY_FOR_SHIPMENT` | |
| 배송중 | 배송조회 가능 | `IN_TRANSIT` | 택배사 송장번호 발급 시점부터 |
| 부분 취소 | 일부 상품 취소 | `PARTIALLY_CANCELLED` | 한 주문 내 일부 SKU만 취소된 상태. 전체 취소(`CANCELLED`)와 구분 |
| PG사 | 결제대행사 | `paymentGateway` | 카드/간편결제 승인을 대행하는 외부사(예: 이니시스, 토스페이먼츠). 코드에서는 `payment-service`가 추상화하여 다룸 |
| CS 처리 | 고객문의 처리 | (해당 없음 — CS 시스템은 별도 도구, commercehub-be 범위 밖) | 개발팀은 CS 요청 시 주문 상태 API/어드민 도구를 제공하는 역할까지만 담당 |

## 회원/혜택

| 기획 용어 | 개발 표준명 | 설명 |
| --- | --- | --- |
| 등급 | `membershipTier` | BRONZE/SILVER/GOLD/VIP 4단계. "회원 등급"과 "쿠폰 등급"은 다른 개념이므로 혼용 금지 |
| 적립금 | `rewardPoint` | 실 결제금액 기준 적립, 유효기간 1년 |
| 쿠폰함 | `couponWallet` | 사용자가 보유한 쿠폰 목록. 발급된 쿠폰(`issuedCoupon`)과 사용 가능한 쿠폰(`usableCoupon`)은 조건(최소주문금액 등)에 따라 다를 수 있음 |

## 장바구니

| 기획 용어 | 개발 표준명 | 설명 |
| --- | --- | --- |
| 장바구니 병합 | `cart merge` | 비로그인 상태 장바구니(로컬 저장)와 로그인 후 서버 장바구니를 합치는 로직. 동일 SKU는 수량을 합산, 최대 수량 초과 시 초과분은 담기지 않고 안내 |
| 최근 본 상품 | `recentlyViewed` | 장바구니와 별개 기능. 재고/가격 변동과 무관하게 조회 이력만 저장 |

## 커뮤니케이션 시 주의사항

- 기획 문서에서 "상품"이라고 쓸 때 SKU 단위인지 상품 단위인지 반드시 명시해야 개발 견적이 정확해집니다.
- 디자이너가 화면 상태명(예: "배송조회 가능")으로 전달한 내용을 개발자가 코드 상태값(`IN_TRANSIT`)으로 오인하지 않도록, 화면 문구는 별도 i18n 리소스로 관리하고 상태 Enum과 1:1로 강제 매핑하지 않습니다(문구는 마케팅 사유로 자주 바뀌지만 상태 Enum은 거의 바뀌지 않음).
- 새로운 용어가 필요하면 기획/디자인/개발 중 누구든 이 문서에 PR로 초안을 올리고, 3자 합의 후 병합합니다.
